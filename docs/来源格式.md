# 采购评审资料来源格式

支持 DOCX ZIP 中 document.xml、comments.xml、commentsExtended.xml 与关系文件。WordprocessingML 主命名空间按 URI 识别。view=accepted 忽略 del、保留 ins；view=original 保留 delText、忽略 ins；view=marked 同时保留两者及状态。文字位置使用原始 run/text 节点路径及 Unicode code point 偏移，段间插入换行，并提供各视图范围映射。批注端点可跨段，id 不代表顺序；commentsExtended paraIdParent 建回复关系。缺端点、重复端点、关系外目标不靠文本匹配修复。

具体约定：

- 范围由同一批注 id 的 commentRangeStart 与 commentRangeEnd 围出的原始文档流决定；原始流包含正文文字、插入文字、删除文字和段间换行，所以三种视图共用同一份原始范围，再各自投影。
- 视图投影按原始流中的 Unicode code point 对齐：被该视图隐藏的文字从视图文字中消失，但两侧端点不移动，因此批注在 accepted 与 original 下仍落在同一处语义文字上。若范围只覆盖被隐藏的文字，该视图给出空范围并置 `empty`，不向相邻文字扩张。
- commentReference 只作辅助定位；缺失时记录 `anchor-reference-missing`，不影响由起止端点确定的文字范围。起点或终点缺失、重复、顺序颠倒时不猜测范围，记录 issue 并保持不可定位。
- 批注 id 与正文标记按去空白后比较，id 大小写不敏感；重复批注 id 视为身份不唯一，不做文本匹配。
- 回复关系只来自 commentsExtended.xml：批注文字首段的 w14:paraId 与 commentEx 的 w15:paraId 对应，w15:paraIdParent 指向上级批注的 paraId。回复不使用自身没有的范围去搜正文，而沿用可定位上级的范围并标记 `inherited`。上级缺失、循环、重复上级或 paraId 冲突时记录关系问题，回复不定位。
- 段间换行不计入任何段内偏移，仅表示段落边界；制表符按一个 code point、换行按一个 code point 计入。
- 关系文件按 Type URI 查找 comments 与 commentsExtended。批注关系指向 word/comments.xml 之外、目标部件缺失、或批注部件不是 WordprocessingML 主命名空间时，结构化收件为 rejected，原文仍保留在 blobs。
- 未支持的批注相关 XML 部件（如 people.xml、commentsIds.xml）保留原文，列入 coverage.unsupportedParts 与 issues，不假装解析。
- 只读取表格、内容控件等结构中的 w:t/w:delText 文字，不重建版式、不编辑文档。

`fixtures/scenarios.json` 给出本机来源入口和允许读取的资源；`GET /manifest` 返回同样的来源描述。`GET /trace` 返回当前进程内真实来源访问记录。资源接口为 `GET /files/百分号编码的资源名`，支持单段 Range、ETag 和 If-Match；资源名必须出现在来源清单中。数据不是新闻原文，不连接真实客户或设备。

格式参考：https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document。本项目只承诺上文列出的范围；未列出扩展应保留原文并明确不支持，不能假装完整解析。
