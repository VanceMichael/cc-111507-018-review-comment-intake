# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 已上线，只领取入口文件并记录元信息。structured 用于 WordprocessingML 审阅资料，view 可选 accepted、original、marked，缺省 accepted；view 只决定记录顶层 `anchor.text` 取哪一种文字，三种视图范围都会同时返回。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

## 结构化审阅记录

records 每条批注一条，`id` 为 `comment-{comment id}`（同一 id 重复出现时追加序号），并保留 `commentId`、作者、日期、批注文字、`replyTo` 与 `threadRoot`。

`anchor` 描述批注在正文中的位置：

- `locatable`：是否得到可复查的文字范围。只有范围起点和终点都唯一存在且顺序有效，或回复的上级范围可定位时，才为 true。
- `markers`：原始标记的无损位置，`starts`、`ends`、`references` 各自列出 `nodePath`（原始 body/p/r/text 节点路径）、Unicode code point `offset` 和段落序号。这些位置取自原始文档流，不随 view 改变。
- `range`：原始文档流中的 code point 起止；`views.accepted`、`views.original`、`views.marked` 各自给出该视图中的 `start`、`end`、`text`、`empty`，以及范围内包含哪些文字类别（`includes.text`、`inserted`、`deleted`、`breaks`）。插入、删除的分支文字可能使另一种视图范围为空，此时 `empty` 为 true，不回退到相邻相同文字。
- `text`：本次 view 覆盖的文字，等于 `views[view].text`。
- `inherited`：回复自身没有正文锚点而沿用上级范围时为 true，同时给出 `parentId`。

无法定位时 `anchor.locatable` 为 false，`anchor.reason` 说明缺口，`anchor.markers` 仍保留已找到的原始标记；对应问题写入 `issues`，code 使用 `anchor-range-incomplete`、`anchor-marker-duplicated`、`anchor-order-invalid`、`comment-without-anchor`、`reply-target-missing`、`reply-cycle`、`anchor-target-missing` 等。任何未解决的定位缺口或关系缺口都会使 state 保持 partial，不使用可见文字搜索补救。

`coverage` 说明读了哪些部件、支持范围、三视图 code point 数、段落数、批注总数、可定位数、继承数、回复数及问题数；`unsupportedParts` 列出包内未解析的 XML 部件。`evidence` 保存来源字节数、来源版本与原文摘要，原文位于 blobs。
